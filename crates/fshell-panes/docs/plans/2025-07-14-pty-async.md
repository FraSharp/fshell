# Phase 2: PTY Management & Async I/O

## Gemini Fixes Applied (2025-07-14)

Three silent runtime traps identified and fixed before implementation:

1. **Double-free on fd** — `AsyncPtyFd` no longer calls `libc::close()` in Drop. The `master: Box<dyn MasterPty>` owns the fd lifecycle. `AsyncPtyFd` is a borrow-only wrapper.
2. **Sync write on non-blocking fd** — `write()` is now `async` with `writable().await` loop. Under PTY pressure, `libc::write` returns `EAGAIN`; the async loop retries instead of dropping bytes.
3. **Grid ownership conflict** — `GridManager` holds `Arc<RwLock<Grid>>` (not direct ownership). Write-locked only during `parser.process()` (~microseconds). UI/tests hold a clone and read-lock during render. No deadlocks because parse is fast and lock scope is minimal.

## Architecture

```
┌─────────────────────────────────────────────────────────────────┐
│                        ASYNC PTY                                │
│                                                                 │
│   ┌─────────────────────┐                    ┌───────────────┐  │
│   │   portable-pty      │  as_raw_fd / libc  │  AsyncFd      │  │
│   │   (Master / Slave)  │ ─────────────────> │  (epoll/kqueue)│  │
│   └─────────────────────┘                    └───────┬───────┘  │
│                                                      │          │
│                                                      ▼          │
│   ┌─────────────────────┐                    ┌───────────────┐  │
│   │  tokio::spawn Task  │ <────────────────  │ Read Readiness│  │
│   │  (Executes parser)  │                    └───────────────┘  │
│   └─────────┬───────────┘                                       │
└─────────────┼───────────────────────────────────────────────────┘
              │ mpsc channel (PtyCommand::Data(Vec<u8>))
              ▼
┌─────────────────────────────────────────────────────────────────┐
│                     GRID MANAGER (Actor)                         │
│                                                                 │
│   ┌──────────────┐    ┌──────────────┐    ┌───────────────┐    │
│   │  Grid        │<───│ GridParser   │<───│ mpsc::Receiver │    │
│   │  (single     │    │ (VTE + Pen)  │    │ (byte chunks)  │    │
│   │   threaded)  │    └──────────────┘    └───────────────┘    │
│   └──────────────┘                                              │
│   ┌──────────────┐                                              │
│   │ dirty regions │──────────────> UI Layer (future)             │
│   └──────────────┘                                              │
└─────────────────────────────────────────────────────────────────┘
```

**Thread-safety**: Actor/message-passing — Grid stays single-threaded inside the GridManager task. No locks, no `Arc<Mutex<>>`.
**Platform**: macOS + Linux only (Unix-native `AsyncFd` with epoll/kqueue). Windows deferred to future phase.

## Data Flow

1. **PTY read loop** (tokio task): awaits read-readiness via `AsyncFd`, does non-blocking `read()` into a stack buffer, sends `PtyCommand::Data(bytes)` over mpsc channel
2. **GridManager** (tokio task): receives byte chunks, feeds them through `GridParser::process()`, which updates the `Grid` and dirty regions
3. **UI layer** (future): polls dirty regions, renders only changed cells via `GridWidget`

## Task 2: Implement `AsyncPty` Wrapper

**Files**: `src/pty/async_pty.rs`, `tests/async_pty_test.rs`

### Struct definition

```rust
use std::os::unix::io::{AsRawFd, RawFd};
use tokio::io::unix::AsyncFd;
use portable_pty::{CommandBuilder, NativePtySystem, PtySize, MasterPty, Child};

/// Wraps a portable-pty master fd in tokio's AsyncFd for non-blocking async I/O.
///
/// SAFETY: `master: Box<dyn MasterPty>` owns the fd lifecycle. `AsyncPtyFd`
/// is a borrow wrapper only — it does NOT close the fd on drop. This avoids
/// double-close when `MasterPty`'s own Drop runs.
pub struct AsyncPty {
    async_fd: AsyncFd<AsyncPtyFd>,  // the non-blocking fd wrapper
    child: Box<dyn Child>,          // the spawned shell process
    master: Box<dyn MasterPty>,     // owns fd lifecycle + resize()
}

/// Borrow-only wrapper around RawFd that implements AsRawFd for AsyncFd.
/// Does NOT own the fd — `master` handles lifecycle.
struct AsyncPtyFd(RawFd);

impl AsRawFd for AsyncPtyFd {
    fn as_raw_fd(&self) -> RawFd {
        self.0
    }
}
// NOTE: No Drop impl — master: Box<dyn MasterPty> handles fd close.
```

### Constructor: `AsyncPty::spawn(shell, cols, rows)`

1. Create `NativePtySystem` and `portable_pty::PtySize { rows, cols }`
2. `pty_system.openpty(size)` → get `(master, slave)`
3. Build `CommandBuilder::new(shell)` (e.g. `/bin/bash`)
4. `slave.spawn_command(command)` → get `Child`
5. Extract raw fd: `master.as_raw_fd()` → `RawFd`
6. **Set non-blocking**: `libc::fcntl(fd, libc::F_SETFL, libc::O_NONBLOCK)`
7. Wrap in `AsyncPtyFd(fd)` → `AsyncFd::new(AsyncPtyFd(fd))`
8. Return `AsyncPty { async_fd, child, master }`

### Async read: `AsyncPty::read(&self, buf: &mut [u8]) -> io::Result<usize>`

```rust
pub async fn read(&self, buf: &mut [u8]) -> io::Result<usize> {
    loop {
        // Wait until the fd is readable (via epoll/kqueue)
        let mut guard = self.async_fd.readable_mut().await?;
        match guard.try_io(|inner| {
            let fd = inner.as_raw_fd();
            unsafe {
                libc::read(fd, buf.as_mut_ptr() as *mut libc::c_void, buf.len())
            }
        }) {
            Ok(Ok(n)) => return Ok(n as usize),    // got data
            Ok(Err(e)) => return Err(e),             // real error
            Err(_would_block) => continue,           // spurious wake, retry
        }
    }
}
```

### Async write: `AsyncPty::write(&self, data: &[u8]) -> io::Result<usize>`

```rust
pub async fn write(&self, data: &[u8]) -> io::Result<usize> {
    loop {
        // Wait until the fd is writable (via epoll/kqueue)
        let mut guard = self.async_fd.writable().await?;
        match guard.try_io(|inner| {
            let fd = inner.as_raw_fd();
            let res = unsafe {
                libc::write(fd, data.as_ptr() as *const libc::c_void, data.len())
            };
            if res < 0 {
                let err = io::Error::last_os_error();
                if err.kind() == io::ErrorKind::WouldBlock {
                    Err(err)  // retry — try_io will return Err(_would_block)
                } else {
                    Ok(Err(err))  // real error
                }
            } else {
                Ok(Ok(res as usize))
            }
        }) {
            Ok(result) => return result,
            Err(_would_block) => continue,  // spurious wake, retry
        }
    }
}
```

**Why async?** The fd is `O_NONBLOCK`. Under PTY pressure (e.g. fast `cat` of large file), `libc::write` returns `EAGAIN`/`EWOULDBLOCK`. An async write loops on `writable().await` so no keystrokes are dropped.

## Task 3: Build the GridManager Run Loop

### Message type

```rust
/// Commands sent from the PTY read loop to the GridManager.
pub enum PtyCommand {
    /// Raw bytes from the PTY — fed through VTE parser.
    Data(Vec<u8>),
    /// Terminal resize request — adjusts grid dimensions.
    Resize(u16, u16),
    /// Clean shutdown signal.
    Shutdown,
}
```

### GridManager struct

```rust
use std::sync::Arc;
use tokio::sync::{mpsc, RwLock};
use crate::grid::{Grid, parser::GridParser};

/// Actor that processes PTY output into a shared Grid.
pub struct GridManager {
    grid: Arc<RwLock<Grid>>,   // shared with UI/tests — write-locked only during parse
    parser: GridParser,
    rx: mpsc::Receiver<PtyCommand>,
}
```

### Constructor

```rust
impl GridManager {
    pub fn new(
        width: usize,
        height: usize,
        scrollback_limit: usize,
        rx: mpsc::Receiver<PtyCommand>,
    ) -> (Self, Arc<RwLock<Grid>>) {
        let grid = Arc::new(RwLock::new(Grid::new(width, height, scrollback_limit)));
        let grid_clone = grid.clone();
        (Self { grid, parser: GridParser::new(), rx }, grid_clone)
    }
}
```

### Run loop

```rust
impl GridManager {
    /// Main actor loop. Call this from a tokio::spawn task.
    pub async fn run(&mut self) {
        while let Some(cmd) = self.rx.recv().await {
            match cmd {
                PtyCommand::Data(bytes) => {
                    // Lock grid for write only during parse (~microseconds)
                    let mut grid = self.grid.write().await;
                    self.parser.process(&mut grid, &bytes);
                    drop(grid);  // release lock immediately
                }
                PtyCommand::Resize(cols, rows) => {
                    let mut grid = self.grid.write().await;
                    grid.resize(cols as usize, rows as usize);
                }
                PtyCommand::Shutdown => {
                    break;
                }
            }
        }
    }
}
```

### Shared Grid access: `Arc<RwLock<Grid>>`

The GridManager holds an `Arc<RwLock<Grid>>` clone. It locks the write guard only during `parser.process()` (microseconds). The UI (or tests) holds another clone and locks the read guard during render.

**Why not pure actor?** Sending the entire viewport (40×120 = 4,800 Cells) over a oneshot every frame is expensive. `RwLock` is zero-copy and parse is fast enough that contention is negligible.


## Post-Phase 2 State

After this phase, the project will have:

```
src/
  grid/          (Phase 1 — complete)
    cell.rs        Cell + Pen (Copy)
    row.rs         Row with dirty tracking
    scrollback.rs  Grid with circular buffer
    parser.rs      VTE parser + SGR
    widget.rs      ratatui Widget
    reflow.rs      Resize placeholder
  pty/           (Phase 2 — this phase)
    mod.rs         Module root
    async_pty.rs   AsyncFd wrapper around portable-pty
    grid_manager.rs Actor task owning Grid + Parser
```

The two components are fully decoupled:
- **Grid layer** knows nothing about PTYs — it's pure data structures
- **PTY layer** feeds bytes into the Grid via the actor channel
- **UI layer** (Phase 3) will render the Grid via `GridWidget` and send resize/input events back

This separation means we can test the Grid parser in isolation, test the PTY read loop in isolation, and only need integration tests for the full pipeline.
